# Shared Library (smsly-core) — Audit Report

**Date:** 2026-07-17
**Scope:** Circuit breakers, direct access protection, OTP, passwords, API keys, trust engine, audit, webhook validators
**Files reviewed:** smsly_core/circuit_breaker/, smsly_core/direct_access/, smsly_core/internal_auth/, smsly_core/otp/, smsly_core/password/, smsly_core/api_keys.py, smsly_core/trust_engine.py, smsly_core/audit/, smsly_core/webhook_validators.py, smsly_core/spiffe_auth.py

---

## Critical (P0)

### C1: OTP Hashed with Raw SHA-256 — Brute-Forceable in Milliseconds
**File:** smsly_core/otp/hashing.py (lines 18-23), smsly_core/otp.py (lines 85-92)
**Issue:** 6-digit numeric OTP has 1,000,000 possible values. SHA-256 computes billions of hashes/second on GPU. Brute-force takes <1ms.
**Impact:** Complete bypass of OTP verification if attacker obtains stored hash + salt from database.
**Fix:** Replace with Argon2id (already available in password module) or PBKDF2 with >=600,000 iterations.

### C2: NonceCache Is In-Memory Only — Replay Attacks in Distributed Deployments
**File:** smsly_core/internal_auth/nonce_cache.py
**Issue:** Each service instance maintains its own nonce cache. Nonce consumed on instance A is unknown to instance B. Full replay attack capability for any inter-service signed request within the 5-minute timestamp window.
**Impact:** Replay attacks across horizontally scaled instances.
**Fix:** Replace with Redis-backed distributed nonce cache: `SET NX EX`.

### C3: Phone Hash Reversible via Rainbow Tables
**File:** smsly_core/trust_engine.py (line 268)
**Issue:** `hashlib.sha256(phone.encode())` with no salt/pepper. Phone numbers have ~33 bits entropy. Complete rainbow table precomputable in seconds.
**Impact:** Full de-anonymization of trust engine's device/IP/session databases.
**Fix:** Use HMAC with server-side pepper.

## High (P1)

### H1: Proof Token Signature Truncated to 128 Bits
**File:** smsly_core/otp/proof_token.py (lines 30-35)
**Issue:** `hexdigest()[:32]` truncates HMAC-SHA256 output to 128 bits. Eliminates collision resistance guarantee.
**Fix:** Use full HMAC output.

### H2: Proof Token Lacks Audience/Issuer Binding
**File:** smsly_core/otp/proof_token.py (lines 22-29)
**Issue:** No `iss`, `aud`, or `sub` claims. Proof token generated by one service can be replayed to any other service.
**Fix:** Add `aud` (intended audience) and `iss` (issuer) claims.

### H3: Audit Chain Uses Unkeyed SHA-256 — Tamperable
**File:** smsly_core/audit/hashing.py (lines 16-35)
**Issue:** Audit chain hash is unkeyed SHA-256. Any attacker with write access to the database can modify events and recompute all subsequent hashes to maintain chain integrity.
**Impact:** Audit log tampering undetectable by chain verification.
**Fix:** Use HMAC with a secret key held separately from the database.

## Positive Findings

- Constant-time comparison (`hmac.compare_digest`) used everywhere for secret/signature comparison
- `secrets` module for all random generation (CSPRNG)
- Argon2id for password hashing with strong parameters (3 iterations, 64MB, parallelism=4)
- Transparent bcrypt→Argon2id migration via `verify_and_upgrade()`
- Body restoration after signature verification (downstream consumers get intact request)
- Gateway signature timestamp freshness (5-minute window)
- UUIDv4 for nonces (122 bits cryptographic entropy)
- Progressive enforcement in direct access (warn 1-2x, then block)
- Circuit breaker with proper CLOSED→OPEN→HALF_OPEN state machine + async lock
- Global breaker registry with `get_breaker()` singleton pattern
- API key generation with `sk_live_`/`sk_test_` prefixes and SHA-256 hashing
- Webhook signature validation for Twilio, WhatsApp, Stripe, Coinbase
- SPIFFE dual-auth module with feature flags, allowed callers registry, and auth metrics

## Resolved Findings (Post-Remediation)

### HMAC Inter-Service Authentication — RESOLVED
**Date:** 2026-07-18
**Resolution:** All HMAC-based inter-service authentication replaced with SPIFFE mTLS (Phase 4).
- `internal_auth.py`: All HMAC functions deprecated with `DeprecationWarning`. Kept for SDK client auth only.
- `auth_middleware.py`: Stripped of all HMAC validation. Now uses `DualAuthValidator` exclusively.
- `gateway_guard.py`: HMAC code replaced with `DualAuthValidator`.
- `direct_access/middleware.py`: Migrated from HMAC to `DualAuthValidator`.
- `__init__.py`: Removed `compute_signature`, `verify_signature`, `create_signed_headers` from public exports.
- `spiffe_auth.py`: `DualAuthValidator` with `MigrationPhase.PHASE_4` as default. Rejects any request without valid SPIFFE ID.

### C1: OTP Hashed with Raw SHA-256 — RESOLVED
**Resolution:** `hash_otp()` changed from raw SHA-256 to Argon2id (reusing password module pattern).

### C2: NonceCache In-Memory Only — RESOLVED
**Resolution:** Added Redis backend (`SET NX EX`). In-memory kept as fallback; fail-closed on Redis failure.

### C3: Phone Hash Reversible — RESOLVED
**Resolution:** `_hash_phone()` now uses HMAC with server-side pepper (`PHONE_HASH_PEPPER`).

### H1: Proof Token Truncated — RESOLVED
**Resolution:** Removed `[:32]` truncation, using full HMAC-SHA256 output.

### H2: Proof Token Lacks Audience/Issuer — RESOLVED
**Resolution:** Added `aud` and `iss` claims. `verify()` accepts `expected_audience`.

### H3: Audit Chain Unkeyed — RESOLVED
**Resolution:** Optional HMAC key from `AUDIT_CHAIN_KEY`; fallback to SHA-256 with warning.

### M7: Stripe Webhook Missing Timestamp — RESOLVED
**Resolution:** Added timestamp freshness check (300s) for Stripe webhooks.
